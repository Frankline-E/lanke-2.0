# CI/CD Pipeline

A pipeline is a series of automated tasks that run in a sequence to produce a final result. In CI/CD pipelines, these tasks are often referred to as stages.

Instead of manually run:

```bash
npm install
npm run test
npm run build
kubectl apply -f deployment.yaml
```

every single time your pipline does it for you.
Over the years, the industry has develop a bunch of tools for managing pipelines. Some of the most popular ones are:

- Jenkins: Which is the OG, highly customizable, but self hosted and heavy
- Gitlab CI/CD: A free and open source alternative to Jenkins which is build right into Gitlab
- CircleCI:
- TravisCI:
- Azure DevOps:

They all automate, build, test, deploy, and more.
But most Devs today prefer to use Github Actions which is a free and open source alternative to Jenkins which is build right into Github. - which means no extra setup or third party login. - It is event driven: which means that it triggers on push PRs, or cron jobs. For short, if you push to your repo, it will run your pipeline. - It has a masive library of pre-built a
ctions, which means that you can just grab community workflows for testing, docker, deployments and more. - It has version control yaml configs, which is where your automation lives right within your repo. so it is easy to audit and reuse.

At its core a github action pipeline is called a workflow.
Workflows lives in you repo in the `.github/workflows` directory.
Each workflow is just a yaml file defining triggers, what events start the workflow, like pushing code, opening a PR, jogs which are a set of tasks each running on its own virtual machine and the steps which are actual commands or actions executed in a job.

So, What is YAML?

- YAML stands for YAML Ain't Markup Language which basically means that YAML is a human readable format for storing data. which is why Kubernetes, Docker Compose, and GitHub Actions use it for configs.

So, to truely master creating pipelines with github actions, you need to understand and master YAML syntax and how to use it.

Onlike other file formats, YAML is whitespace sensitive, so you need to be careful when writing it. Indentation matters. YAML also have specific keywords and syntax rules some of are:

- `#` for comments
- `-` for lists
- `:` for key value pairs
- `|` for multiline strings
- `name`: `value` for key value pairs (use to define the workflow/job title)
- `on`: `push`,`pull_request`, or `schedule` for triggers
- `jobs`: `build`, `test`, `deploy` for jobs, their OS, and steps
- `steps`: `name`, `run`, `uses` for steps, sequencial commands or actions.
- `run`: for shell commands to execute
- `uses`: for prebuilt actions to run
- `with`: for inputs to the action
- `env`: for environment variables to use in the pipeline
- `secrets`: for secrets to use in the pipeline
- `outputs`: for outputs to use in the pipeline
- `needs`: for other workflows to use in the pipeline

# Create a github action pipeline (using YAML)

1. Dot GitHub
   - Create a `.github` directory in your projec root
   - Create a `workflows` directory in the `.github` directory
   - Create a `main.yml` file in the `workflows` directory
     ```yaml
     name: CI/CD
     on: [push]
     jobs:
       build:
         runs-on: ubuntu-latest
         steps:
           - uses: actions/checkout@v3
           - uses: actions/setup-node@v3
             with:
               node-version: 16
           - run: npm install
           - run: npm run build
     ```
2. Head over to your github repository (https://github.com/username/reponame)
